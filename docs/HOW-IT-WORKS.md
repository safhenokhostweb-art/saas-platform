## ۱. معماری کلی

```
┌─────────────────────────────────────────────────────────────────┐
│                     saas-platform (پنل شما)                       │
│  • مشتریان، سایت‌ها، لایسنس، ماژول‌ها، فرم‌ها، محصولات، فروشگاه   │
│  • API: لایسنس، سایت‌کانفیگ، بروزرسانی                            │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                    درخواست HTTP (API)
                                │
        ┌───────────────────────┼───────────────────────┐
        │                       │                       │
        ▼                       ▼                       ▼
┌───────────────┐       ┌───────────────┐       ┌───────────────┐
│ customer-site │       │ customer-site │       │ customer-site │
│  (سایت الف)   │       │  (سایت ب)     │       │  (سایت ج)     │
│  هاست مشتری ۱ │       │  هاست مشتری ۲ │       │  هاست مشتری ۳ │
└───────────────┘       └───────────────┘       └───────────────┘
```

- **پلتفرم** یک دیتابیس دارد و همهٔ سایت‌ها را مدیریت می‌کند.
- **هر سایت مشتری** یک نصب جدا روی هاست خودش دارد و دیتابیس خودش را دارد.
- سایت‌های مشتری برای **لایسنس**، **ماژول‌ها** و **ظاهر (UX)** به API پلتفرم متصل می‌شوند.

## ۲. دو پروژه و نقش هر کدام

### saas-platform (پنل مدیر اصلی)

| کار | کجا انجام می‌شود |
|-----|------------------|
| ثبت مشتری | مشتری‌ها → افزودن |
| ایجاد سایت برای مشتری | سایت‌ها → افزودن |
| تعیین ماژول‌های هر سایت | سایت‌ها → ویرایش → ماژول‌ها |
| صدور لایسنس | سایت‌ها → لایسنس → صدور |
| تعریف فرم‌ها | فرم‌ها |
| تعریف صفحات ثابت و راهنما | صفحات ثابت و راهنما |
| تنظیم ظاهر (رنگ، فونت، لوگو) | تنظیمات عمومی پلتفرم |
| تعریف محصولات فروشگاه | محصولات فروشگاه |
| پلن‌های پشتیبانی | پلن‌های پشتیبانی |
| نمایندگان و کمیسیون | نمایندگان، تسویه کمیسیون |
| درخواست‌های تسویه نمایندگان | درخواست‌های تسویه |
| تیکت‌های پشتیبانی | تیکت‌های پشتیبانی |

**قانون:** همهٔ مدیریت‌ها فقط از پلتفرم انجام می‌شود. سایت مشتری **هیچ‌چیز** را مستقل تعریف نمی‌کند.

---

### customer-site (سایت هر مشتری)

| کار | کجا انجام می‌شود |
|-----|------------------|
| محتوای صفحات | ادمین → صفحات |
| مطالب وبلاگ | ادمین → مطالب |
| محصولات فروشگاه (محلی) | ادمین → محصولات |
| سفارشات | ادمین → سفارشات |
| تنظیمات سایت (نام، تم، درباره ما) | ادمین → تنظیمات |
| **فعال‌سازی لایسنس** | ادمین → لایسنس |
| بروزرسانی نرم‌افزار | ادمین → لایسنس → بررسی بروزرسانی |

**قانون:** سایت مشتری فقط **محتوا** و **تنظیمات محلی** را مدیریت می‌کند. لایسنس، ماژول‌ها و ظاهر از پلتفرم می‌آیند.

## ۳. جریان داده: پلتفرم → سایت مشتری

```
سایت مشتری                    پلتفرم
     │                            │
     │  ۱. POST /api/license/validate
     │     (license_key, domain)   │
     ├───────────────────────────►│
     │                            │  بررسی: کلید معتبر؟ دامنه درست؟ سایت فعال؟
     │  ۲. پاسخ: valid, modules, support_expires_at
     │◄───────────────────────────┤
     │                            │
     │  ۳. GET /api/site-config?license_key=...&domain=...
     ├───────────────────────────►│
     │                            │  برگرداندن: ماژول‌ها، UX (رنگ، فونت، لوگو)
     │  ۴. پاسخ: allowed, modules, ux
     │◄───────────────────────────┤
     │                            │
     │  (کش UX برای ۱ ساعت)       │
     │                            │
```

- **مرحله ۱–۲:** هنگام فعال‌سازی لایسنس در پنل سایت مشتری.
- **مرحله ۳–۴:** هنگام بارگذاری صفحات (ورود، داشبورد، و غیره) برای دریافت ظاهر و ماژول‌ها.

---

## ۴. مراحل کار از دید شما (مدیر پلتفرم)

### مرحله ۱: راه‌اندازی اولیه پلتفرم
1. نصب saas-platform روی سرور خودتان.
2. اجرای مایگریشن‌ها و ساخت ادمین اولیه.
3. ورود به پنل با موبایل و رمز عبور.

### مرحله ۲: ثبت مشتری جدید
1. مشتری‌ها → افزودن مشتری.
2. نام، شرکت، ایمیل، موبایل، نماینده (اختیاری).

### مرحله ۳: ایجاد سایت برای مشتری
1. سایت‌ها → افزودن سایت.
2. انتخاب مشتری، عنوان، دامنه (مثلاً `shop.example.ir`).
3. انتخاب ماژول‌ها (blog، shop و غیره).
4. تعیین تاریخ انقضای پشتیبانی (اختیاری).

### مرحله ۴: صدور لایسنس
1. سایت‌ها → انتخاب سایت → لایسنس → صدور لایسنس.
2. دامنهٔ مجاز را وارد کنید (یا خالی برای هر دامنه).
3. کلید لایسنس را کپی و به مشتری بدهید (فقط یک‌بار نمایش داده می‌شود).

### مرحله ۵: تحویل به مشتری
- کپی پروژه customer-site را روی هاست مشتری آپلود کنید.
- کلید لایسنس را به مشتری بدهید.
- مشتری در پنل خود → لایسنس، کلید و دامنه را وارد و فعال می‌کند.

---

## ۵. مراحل کار از دید مشتری

### مرحله ۱: دریافت سایت
- شما (یا مشتری) پروژه customer-site را روی هاست مشتری نصب می‌کنید.
- دیتابیس ایجاد و در `.env` تنظیم می‌شود.
- `composer install` و `php artisan migrate` اجرا می‌شوند.

### مرحله ۲: نصب از مرورگر
- باز کردن آدرس سایت → ویزارد نصب (`/install`).
- وارد کردن اطلاعات دیتابیس، نام، موبایل، ایمیل و رمز ادمین.

### مرحله ۳: فعال‌سازی لایسنس
- ورود به پنل با موبایل و رمز عبور.
- ادمین → لایسنس.
- وارد کردن کلید لایسنس و دامنه → فعال‌سازی.
- در صورت موفقیت، ماژول‌ها و تاریخ پشتیبانی از پلتفرم دریافت و ذخیره می‌شوند.

### مرحله ۴: مدیریت محتوا
- صفحات، مطالب وبلاگ، محصولات و سفارشات را از پنل مدیریت می‌کند.
- ظاهر (رنگ، فونت، لوگو) از پلتفرم می‌آید و در سایت اعمال می‌شود.

## ۶. جریان لایسنس (شماره‌گذاری شده)

```
۱. شما در پلتفرم: سایت‌ها → سایت X → لایسنس → صدور لایسنس
   → دامنه: shop.example.ir
   → کلید تولید و یک‌بار نمایش داده می‌شود.

۲. کلید را به مشتری می‌دهید.

۳. مشتری در سایت خود: ادمین → لایسنس
   → کلید و دامنه (shop.example.ir) را وارد می‌کند.

۴. سایت مشتری به پلتفرم درخواست می‌فرستد:
   POST /api/license/validate
   { "license_key": "...", "domain": "shop.example.ir" }

۵. پلتفرم بررسی می‌کند:
   - کلید در platform_licenses وجود دارد؟
   - دامنه مطابقت دارد؟ (یا خالی = هر دامنه)
   - لایسنس لغو نشده؟ منقضی نشده؟
   - سایت فعال است؟

۶. در صورت موفقیت، پاسخ برمی‌گرداند:
   { "valid": true, "modules": ["blog","shop"], "support_expires_at": "..." }

۷. سایت مشتری این اطلاعات را در جدول licenses ذخیره می‌کند.
   از این به بعد، ماژول‌ها و تاریخ پشتیبانی در سایت مشتری موجود است.
```

## ۷. جریان خرید و پرداخت

(در صورت استفاده از فروشگاه پلتفرم)

```
۱. مشتری در پلتفرم ثبت‌نام می‌کند (یا قبلاً ثبت‌نام کرده).

۲. به فروشگاه پلتفرم می‌رود (/store).
   محصولات: لایسنس قالب، ماژول افزودنی، پلن پشتیبانی.

۳. محصول را به سبد اضافه می‌کند.
   برای ماژول/پشتیبانی: سایت موردنظر را انتخاب می‌کند.

۴. تسویه → درگاه زرین‌پال → پرداخت.

۵. پس از پرداخت موفق:
   - OrderFulfillmentService اجرا می‌شود.
   - برای لایسنس: صدور خودکار و ارسال به مشتری.
   - برای ماژول: الحاق به سایت.
   - برای پشتیبانی: تمدید support_expires_at.
   - برای نماینده: ثبت کمیسیون در reseller_commissions.
```

## ۸. ماژول‌ها چطور کار می‌کنند؟

### در پلتفرم
- ماژول‌ها در جدول `modules` تعریف شده‌اند (blog، shop، installment و غیره).
- برای هر سایت در `site_modules` مشخص می‌شود کدام ماژول فعال است.
- API لایسنس و سایت‌کانفیگ لیست slug ماژول‌های فعال را برمی‌گردانند.

### در سایت مشتری
- ماژول‌های قابل استفاده در `config/modules.php` تعریف شده‌اند.
- فعال/غیرفعال واقعی با `.env` کنترل می‌شود: `MODULE_BLOG_ENABLED`، `MODULE_SHOP_ENABLED`.
- لیست ماژول‌های دریافتی از پلتفرم در مدل `License` (فیلد `modules`) ذخیره می‌شود.
- در داشبورد، بلوک «ماژول‌ها و امکانات از پلتفرم» نمایش داده می‌شود.

### منطق
- اگر ماژول در لایسنس باشد **و** در `.env` فعال باشد → در سایت نمایش داده می‌شود.
- اگر در لایسنس نباشد → حتی با فعال بودن در `.env`، آن قابلیت در آن سایت نباید فعال شود (بر اساس طراحی).

## ۹. جریان UX و ظاهر سایت

```
۱. شما در پلتفرم: تنظیمات عمومی پلتفرم
   → نام پلتفرم، لوگو، رنگ‌ها، فونت‌ها، ویجت راهنما.

۲. این تنظیمات در جدول settings ذخیره می‌شوند.

۳. سایت مشتری با لایسنس معتبر به API درخواست می‌زند:
   GET /api/site-config?license_key=...&domain=...

۴. پاسخ شامل ux است:
   { "ux": { "general": {...}, "theme": {...}, "font": {...}, "guide_widget": {...} } }

۵. PlatformUxService در customer-site این را کش می‌کند (پیش‌فرض ۵ دقیقه).

۶. صفحات ورود و پنل ادمین سایت مشتری از همین UX استفاده می‌کنند.
   → همان رنگ، فونت و لوگوی پلتفرم در سایت مشتری نمایش داده می‌شود.
```

## ۱۰. سیستم نمایندگی (Reseller)

```
۱. شما یک کاربر را به Reseller تبدیل می‌کنید.
   ادمین → نمایندگان → افزودن → انتخاب کاربر، نرخ کمیسیون.

۲. هنگام ثبت مشتری، فیلد «نماینده» را پر می‌کنید.
   → customer.reseller_id = آن Reseller

۳. وقتی این مشتری خرید می‌کند و پرداخت موفق است:
   → یک رکورد در reseller_commissions ایجاد می‌شود.
   → مبلغ = مبلغ فاکتور × نرخ کمیسیون / 100

۴. Reseller در داشبورد خود (/reseller/dashboard):
   → لیست مشتریان، جمع فروش، لیست کمیسیون‌ها.

۵. Reseller می‌تواند «درخواست تسویه» بزند.
   → رکورد در payout_requests ایجاد می‌شود.

۶. شما در ادمین → درخواست‌های تسویه:
   → تأیید یا رد درخواست.
   → با تأیید، وضعیت کمیسیون‌ها به «پرداخت‌شده» تغییر می‌کند.
```

## ۱۱. خلاصهٔ فنی

### APIهای پلتفرم
| مسیر | روش | کاربرد |
|------|-----|--------|
| `/api/license/validate` | POST | اعتبارسنجی لایسنس |
| `/api/site-config` | GET | دریافت ماژول‌ها و UX |
| `/api/updates/check` | GET | بررسی بروزرسانی |

### جداول کلیدی
| پروژه | جدول | نقش |
|-------|------|-----|
| پلتفرم | `sites` | سایت‌های مشتری |
| پلتفرم | `site_modules` | ماژول‌های هر سایت |
| پلتفرم | `platform_licenses` | لایسنس‌های صادرشده |
| پلتفرم | `customers` | مشتریان |
| پلتفرم | `products`, `invoices` | فروشگاه و فاکتورها |
| سایت مشتری | `licenses` | لایسنس فعال (کپی از پلتفرم) |
| سایت مشتری | `pages`, `posts`, `products` | محتوای سایت |

### متغیرهای مهم .env
| پروژه | متغیر | توضیح |
|-------|-------|--------|
| customer-site | `PLATFORM_URL` | آدرس پلتفرم (برای API) |
| customer-site | `OWNER_SITE` | `true` = سایت مالک (callback بانک + صفحهٔ محصولات پلتفرم) |
| customer-site | `MODULE_BLOG_ENABLED` | فعال بودن وبلاگ |
| customer-site | `MODULE_SHOP_ENABLED` | فعال بودن فروشگاه |
| پلتفرم | `ZARINPAL_MERCHANT_ID` | درگاه پرداخت |
| پلتفرم | `PAYMENT_CALLBACK_URL` | دامنهٔ callback بانک (مثلاً safhenokhost.ir) |
