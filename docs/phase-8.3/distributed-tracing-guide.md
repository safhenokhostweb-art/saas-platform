# Distributed Tracing Guide — Phase 8.3

## How Tracing Works

Every HTTP request gets a `trace_id` either from the `X-Trace-Id` incoming header or auto-generated by `CorrelationIdMiddleware`. This ID is:

1. Stored in `TelemetryContext` singleton for the request lifecycle
2. Written to every telemetry event emitted during the request
3. Echoed back to the caller via `X-Trace-Id` response header
4. Serialized into queue job payloads via `RequestTraceManager::forQueuePayload()`

## Trace Propagation Flow

```
HTTP Client (X-Trace-Id: abc)
  ↓
CorrelationIdMiddleware (reads header, sets TelemetryContext)
  ↓
Application code (reads TelemetryContext, emits events with trace_id=abc)
  ↓
Queue Dispatch (serializes forQueuePayload() → parent_trace_id=abc)
  ↓
Job Handler (calls restoreFromQueuePayload(), TelemetryContext.trace_id=abc)
  ↓
telemetry_events table (all rows share trace_id=abc)
```

## Querying a Trace

```bash
# All telemetry events for a trace:
php artisan tinker
>>> app(\SaaSPlatform\CoreUtils\Telemetry\TelemetryManager::class)->query(['trace_id' => 'abc-123'])

# Reconstruct the full incident timeline:
>>> app(\SaaSPlatform\CoreUtils\Telemetry\Incident\IncidentReconstructionService::class)->reconstruct('abc-123')

# Replay events for a trace:
>>> app(\SaaSPlatform\CoreUtils\Telemetry\Incident\TraceReplayService::class)->replay('abc-123')
```

## Propagating Trace to Outbound HTTP

When making outbound HTTP calls (e.g., license server, external APIs), include the propagation headers:

```php
$headers = app(RequestTraceManager::class)->propagationHeaders();
// Returns: ['X-Trace-Id' => '...', 'X-Request-Id' => '...', 'X-Release-Id' => '...']

Http::withHeaders($headers)->get('https://external-service/api');
```

## CLI Tracing

Console commands get auto-generated `cli-{uuid}` trace IDs if `initForConsole()` is called:

```php
app(RequestTraceManager::class)->initForConsole();
```
